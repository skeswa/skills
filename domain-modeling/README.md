# domain-modeling

Actively builds and sharpens a project's domain model while you design: challenges terms that conflict with the glossary, forces precision on fuzzy ones, stress-tests relationships with edge-case scenarios, cross-checks claims against the code, and writes results down the moment they land — terms into `CONTEXT.md`, hard-to-reverse trade-offs into an ADR under `docs/adr/`. Both files are created lazily.

It's the _active_ discipline. Merely reading `CONTEXT.md` for vocabulary isn't this skill.
