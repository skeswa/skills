# codebase-design

The shared vocabulary for designing **deep modules** — a lot of behaviour behind a small interface, at a clean seam. Fixes the terms (module, interface, implementation, depth, seam, adapter, leverage, locality) and the principles (the deletion test, "the interface is the test surface", "one adapter = hypothetical seam, two = real"), so every other design skill talks about architecture the same way.

Mostly a reference skill — it fires when you're designing or improving a module's interface, or when another skill needs the vocabulary.

## Origin

Copied verbatim from [Matt Pocock's `skills` repo](https://github.com/mattpocock/skills) — specifically [`skills/engineering/codebase-design`](https://github.com/mattpocock/skills/tree/main/skills/engineering/codebase-design). Includes `SKILL.md` plus the linked references: `DEEPENING.md` (dependency categories, seam discipline, replace-don't-layer testing) and `DESIGN-IT-TWICE.md` (the parallel sub-agent pattern for designing an interface several radically different ways).
